{% extends "history.html" %} {% from "macros.html" import decade, event, reference %} {% set page_heading = "History of the World Wide Web" %} {% set headings = {"intro": "Introduction", "timeline": "Timeline", "sources": "References"} %} {% set decades = ["1980s", "1990s", "2000s", "2010s", "2020s"] %} {% block intro %}

A lot of people mix up the Web and the Internet, but they're different. The Internet is the network. The Web is something that runs on top of it, the same way email or online games do. The Internet had already existed for about twenty years before the Web came along. The Web was made by one person, Tim Berners-Lee, while he was working at CERN, and he wrote his first proposal for it in 1989. He had a simple problem: the scientists there kept their work on different computers that couldn't talk to each other, and things got lost whenever people moved on. CERN was already running on TCP/IP by then, so he didn't have to build a network – he only had to come up with a way to link documents together over the one they already had.

{% endblock %} {% block timeline %} {% call decade("1980s") %} {% call event("ENQUIRE", "1980", datetime="1980") %}

On a six-month contract at CERN, Tim Berners-Lee wrote ENQUIRE, a personal note-keeping program in which documents linked to one another. It was never released.

It was the conceptual seed of the Web – linked records rather than a rigid hierarchy – nine years before the proposal.

Source: CERN FAQ, The birth of the Web

{% endcall %} {% call event("CERN standardises on TCP/IP", "1984–1989") %}

Berners-Lee returned to CERN as a fellow in 1984. CERN, previously running a mix of DECnet and other protocols, standardised internally on TCP/IP and by 1989 was the largest Internet site in Europe.

A global open network already existed for the Web to run on. Berners-Lee did not have to invent transport, only the document layer. This is the exact join between the history of the Internet and the history of the Web.

Source: CERN, A short history of the Web

{% endcall %} {% call event("\"Information Management: A Proposal\"", "1989", detail="March", datetime="1989-03", major=true) %}

Berners-Lee submitted the founding document to his manager Mike Sendall, who annotated the cover "Vague but exciting...". It was not formally approved, but he was allowed to work on it. Nothing was built yet.

It named a problem specific to CERN – thousands of physicists rotating through, documentation scattered across incompatible machines, knowledge lost when people left – and proposed distributed hypertext over the existing network as the answer.

Source: Berners-Lee (1989), Information Management: A Proposal

{% endcall %} {% endcall %} {% call decade("1990s") %} {% call event("The formal proposal and the name", "1990", detail="November", datetime="1990-11") %}

After recirculating the 1989 proposal in May 1990, Berners-Lee and Robert Cailliau submitted the formal management proposal, "WorldWideWeb: Proposal for a HyperText Project", dated 12 November 1990. This is where the project got its name. Berners-Lee was given a NeXT computer, whose object-oriented toolkit is why a browser could be built in a few months.

The project was named, approved and resourced.

Source: Berners-Lee & Cailliau (1990), WorldWideWeb: Proposal for a HyperText Project

{% endcall %} {% call event("HTML, HTTP and URLs are built", "1990", detail="Late", datetime="1990", major=true) %}

By Christmas 1990 Berners-Lee had defined and implemented HTML (borrowing from SGML), HTTP and URLs, and had written the first browser (WorldWideWeb, which was also an editor) and the first web server, running on info.cern.ch.

The Web went from proposal to working system. Everything on the Web today descends from those three specifications, which were kept deliberately simple so that anyone could implement them.

Source: W3C, the original HTTP/0.9 specification as implemented

{% endcall %} {% call event("The Web goes public", "1991", detail="6 August", datetime="1991-08-06") %}

Nicola Pellow wrote the line-mode browser, a text-only client that ran on any terminal. On 6 August 1991 Berners-Lee posted the software to the alt.hypertext newsgroup. In December 1991 SLAC in California ran the first web server outside Europe.

The line-mode browser made the Web usable off NeXT machines, and the newsgroup post was the moment it left CERN.

Source: Berners-Lee, alt.hypertext announcement post, 6 August 1991

{% endcall %} {% call event("The Web spreads, then Mosaic arrives", "1992–1993") %}

Roughly 26 web servers existed at the end of 1992 and about 500 by the end of 1993. NCSA released the Mosaic browser in 1993, with inline images and versions for Windows and Mac.

Mosaic turned the Web from a physicists' tool into something the general public wanted to use.

Source: W3C, A Little History of the World Wide Web

{% endcall %} {% call event("CERN puts the Web in the public domain", "1993", detail="30 April", datetime="1993-04-30", major=true) %}

CERN formally waived all rights to the World Wide Web software. Anyone could build servers, browsers or sites without paying or asking.

This was the most consequential decision in the story. Compare Gopher: earlier in 1993 the University of Minnesota announced it might charge licence fees, and Gopher adoption collapsed almost immediately. Openness is why the Web won and why it is a public commons, not a product.

Source: CERN timeline, CERN puts the World Wide Web in the public domain

{% endcall %} {% call event("The first International WWW Conference", "1994", detail="May", datetime="1994-05") %}

Held at CERN and heavily oversubscribed, with around 400 attendees. It was nicknamed the "Woodstock of the Web".

It was the point at which the Web community became larger than CERN itself.

Source: CERN Web@30, web history

{% endcall %} {% call event("Handover to W3C", "1994", detail="October", datetime="1994-10") %}

Berners-Lee left CERN for MIT in October 1994 and founded the World Wide Web Consortium on 1 October 1994. In December, CERN's council decided to concentrate its resources on the Large Hadron Collider and transferred Web development to W3C and INRIA.

This put Web standards in a neutral, vendor-independent body exactly as the browser wars began, rather than leaving them with one physics lab or one company.

Source: W3C, History of the World Wide Web Consortium

{% endcall %} {% call event("The standards are written down", "1994–1996") %}

URL syntax was published as RFC 1738 in December 1994, HTML 2.0 as RFC 1866 in November 1995, and HTTP/1.0 as RFC 1945 in May 1996. CSS Level 1 became a W3C Recommendation in December 1996.

It turned informal practice into written standards that independent browser makers could implement consistently.

Source: RFC 1866, HTML 2.0 and RFC 1945, HTTP/1.0

{% endcall %} {% call event("HTTP/1.1", "1997–1999") %}

HTTP/1.1 was published as RFC 2068 in 1997 and revised as RFC 2616 in June 1999.

It added persistent connections and the Host header, which let many websites share a single IP address. It remained the dominant version of the protocol for about fifteen years.

Source: RFC 2616, HTTP/1.1

{% endcall %} {% endcall %} {% call decade("2000s") %} {% call event("WHATWG forms and the Web becomes an application platform", "2004", datetime="2004") %}

Browser makers formed the Web Hypertext Application Technology Working Group, unhappy that standards work had turned toward XHTML and away from the Web as people actually built it. The same year, applications like Gmail showed that a page could update without reloading.

It set the Web on the path from a document system toward an application platform, and created a split in standards authority that took fifteen years to resolve.

Source: WHATWG

{% endcall %} {% endcall %} {% call decade("2010s") %} {% call event("HTML5 becomes a W3C Recommendation", "2014", detail="28 October", datetime="2014-10-28") %}

HTML5 was published as a W3C Recommendation on 28 October 2014, after roughly eight years of work. It added the semantic elements this page is built from, along with native audio, video and canvas.

Before it, layout meant nested div elements and video meant a plug-in. HTML5 gave structure back its meaning and made media part of the language itself.

Source: W3C, HTML5 Recommendation

{% endcall %} {% call event("WebAssembly ships in every major browser", "2017", datetime="2017") %}

WebAssembly, a portable low-level bytecode format that runs alongside JavaScript, reached its first stable version and shipped in all major browsers.

For twenty years JavaScript was the only language a browser would execute. WebAssembly made the browser a target for compiled languages too.

Source: WebAssembly

{% endcall %} {% call event("One HTML standard again, and the end of Flash", "2019–2020") %}

In 2019 the W3C and WHATWG agreed that WHATWG's HTML Living Standard would be the single version of HTML, ending the fork that began in 2004. In December 2020, Adobe Flash reached end of life.

Both settled long-running arguments in favour of the open Web: one standard rather than two, and open formats rather than a proprietary plug-in.

Source: WHATWG and Adobe, Flash Player end of life

{% endcall %} {% endcall %} {% call decade("2020s") %} {% call event("HTTP/3 moves the Web off TCP", "2022", detail="June", datetime="2022-06") %}

HTTP/3 was published as RFC 9114, running HTTP over QUIC instead of TCP. By 2026 it is supported by more than 95% of browsers in use and serves around 40% of the top ten million websites.

Berners-Lee's original HTTP was a single line of text sent over a TCP connection. The meaning of a request has barely changed since; how it travels has now been rebuilt three times.

Source: RFC 9114, HTTP/3; 2026 figures from Can I Use, HTTP/3 browser support and W3Techs, usage statistics of HTTP/3

{% endcall %} {% call event("Where the Web is now", "2026", datetime="2026") %}

Around 95% of page loads in the United States are encrypted, IPv6 passed half of Google's traffic in March 2026, and HTTP/3 carries a growing share of requests. The three technologies Berners-Lee defined by Christmas 1990, HTML, URLs and HTTP, are all still in use.

Every layer beneath them has been replaced at least once, and the addressing scheme underneath is being replaced now. The design held because it assumed as little as possible about what sat below it.

Source: Let's Encrypt statistics and Google IPv6 statistics
